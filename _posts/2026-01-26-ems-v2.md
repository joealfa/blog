I'm excited to share my latest project: **Employee Management System v2** — a comprehensive full-stack application for managing employees, persons, schools, and related records. This project showcases modern development practices with Clean Architecture on the backend and a React-based frontend.

You can find the source code on GitHub: [https://github.com/joealfa/ems-v2](https://github.com/joealfa/ems-v2)

## Project Overview

The Employee Management System is designed to handle the complexities of workforce management, including person records, employment tracking, positions, salary grades, and document storage. It's built with scalability and maintainability in mind, following industry best practices.

## Technology Stack

### Backend (.NET 10)

The server-side is built with the latest .NET 10, implementing Clean Architecture for maximum separation of concerns:

- **ASP.NET Core** — RESTful Web API framework
- **Clean Architecture** — Domain, Application, Infrastructure, and API layers
- **Entity Framework Core** — ORM for SQL database operations
- **Azure Blob Storage** — Cloud-based document and file storage
- **JWT Authentication** — Secure API authentication with HttpOnly cookies for refresh tokens
- **Swagger/OpenAPI** — Interactive API documentation and client generation
- **xUnit** — Comprehensive testing framework

### Frontend (React 19)

The client application leverages modern React with TypeScript:

- **React 19** — Latest version with improved performance
- **TypeScript** — Full static typing for better developer experience
- **Vite** — Lightning-fast build tool and dev server
- **Chakra-UI** — Accessible and customizable component library
- **AG Grid** — Enterprise-grade data grid for complex data display
- **Axios** — Promise-based HTTP client
- **React Router** — Declarative client-side routing
- **OpenAPI Generator** — Auto-generated, type-safe API client

## Architecture

One of the key aspects of this project is the **Clean Architecture** implementation on the backend:

```
server/
├── EmployeeManagementSystem.Domain/        # Entities and domain logic
├── EmployeeManagementSystem.Application/   # Business logic and DTOs
├── EmployeeManagementSystem.Infrastructure/ # Data access and external services
├── EmployeeManagementSystem.Api/           # API controllers (v1, v2)
└── tests/                                   # Unit and integration tests
```

This layered approach ensures:

- **Independence** — Business logic doesn't depend on frameworks or databases
- **Testability** — Each layer can be tested in isolation
- **Flexibility** — Easy to swap implementations (e.g., different database providers)
- **Maintainability** — Clear boundaries make the codebase easier to navigate

## Features

### Person & Employment Management

Create, update, and manage comprehensive person records with full employment history tracking. The system handles complex relationships between employees, their positions, and organizational structure.

### Position & Salary Grade Configuration

Define and manage job positions with configurable salary grade structures. This provides flexibility for different organizational compensation models.

### School Management

Manage educational institutions and their relationships to employee records — useful for tracking educational backgrounds and institutional affiliations.

### Document Storage with Azure Blob Storage

Secure document upload and management powered by Azure Blob Storage. Documents are organized and accessible through the API with proper authentication.

### Item Inventory

Track items and inventory associated with employees or departments.

### Reporting

Generate various reports for workforce analytics and management insights.

### Secure Authentication

The authentication system uses JWT access tokens combined with HttpOnly cookies for refresh tokens, providing a secure yet seamless user experience.

## API Design

The API follows REST best practices:

- **Lowercase URLs** — All routes use lowercase (e.g., `/api/v1/persons`, `/api/v1/salarygrades`)
- **URL-based Versioning** — Easy API evolution with v1, v2 support
- **OpenAPI/Swagger** — Complete API documentation enabling automatic client generation

### Auto-Generated API Client

One of the productivity boosters is the auto-generated TypeScript API client:

```bash
cd application
npm run generate-api
```

This command generates a fully typed API client from the OpenAPI specification, ensuring the frontend always stays in sync with backend changes.

## Frontend Architecture

The React application is organized for scalability:

```
application/src/
├── api/          # Auto-generated API client
├── components/   # Reusable UI components
├── contexts/     # React context providers
├── hooks/        # Custom React hooks
├── pages/        # Page components
└── theme/        # Chakra-UI theme configuration
```

Using Chakra-UI provides a consistent design system with accessibility built-in, while AG Grid handles complex data display requirements with features like sorting, filtering, and pagination out of the box.

## Getting Started

### Prerequisites

- .NET 10 SDK
- Node.js 18+ and npm
- SQL Server (LocalDB or SQL Server Express)
- Azure Storage Account (for blob storage)

### Running the Backend

```bash
cd server
dotnet restore
dotnet build
cd EmployeeManagementSystem.Api
dotnet run --launch-profile https
```

The API will be available at `https://localhost:5001/` with Swagger UI for interactive testing.

### Running the Frontend

```bash
cd application
npm install
npm run dev
```

The application will be available at `http://localhost:5173/`

## Lessons Learned

Building this project reinforced several important concepts:

1. **Clean Architecture pays off** — The initial setup takes longer, but the maintainability benefits are worth it
2. **Auto-generated clients save time** — OpenAPI Generator eliminates manual API client maintenance
3. **Type safety everywhere** — TypeScript on the frontend and C# on the backend catch errors early
4. **Azure Blob Storage is powerful** — Easy integration for document management at any scale
